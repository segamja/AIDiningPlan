## 전체 구현 계획

이 프로젝트는 문서 `AI_Dining_Plan_프로젝트_개발명세서.md`와 디자인 가이드 `DESIGN.md`, 참조 시안 폴더 `stitch_ai_dining_plan_design`를 기준으로, “현재 위치 기반 추천 → AI 분석 → Dining Plan 생성 → 지도 시각화”의 흐름으로 구현하는 것이 가장 자연스럽습니다.

핵심은 다음 순서입니다:
1. 입력 화면과 레이아웃을 먼저 만들기
2. 위치 수집 및 Kakao 검색 연결
3. AI 추천 로직 연결
4. 식당 + 카페 계획 UI 구성
5. 지도와 카드 동기화
6. 예외 처리와 배포

---

## 1. 구현 우선순위

### 1) 프로젝트 초기 셋업
- React + Vite + TypeScript 기반 앱 구조 구성
- Tailwind 또는 비슷한 스타일 시스템 적용
- 환경 변수 설계: Kakao REST 키, Kakao JavaScript 키, OpenAI API 키
- 기본 앱 레이아웃 구성: 좌측 패널 + 우측 지도

### 2) 디자인 시스템 반영
- warm gourmet 색상 체계 반영
- 카드, 버튼, 뱃지, 라벨, 타임라인 스타일 통일
- 모바일 중심 레이아웃으로 UX 정리
- 시안에서 강하게 보이는 구조: 좌측 플랜 카드 + 우측 지도, 상단 검색/상태 바

### 3) 위치 기반 기능
- 브라우저 위치 권한 요청
- 현재 좌표 확보
- 좌표 기반 Kakao Local 검색
- 위치 거부 시 대체 흐름 준비
- 검색 반경, 정렬, 거리 계산 로직 정리

### 4) Kakao API 연동
- 식당 검색
- 선택된 식당 기준 근처 카페 검색
- 결과 정제: 이름, 주소, 거리, 좌표, 카테고리, URL
- 응답이 없을 때 fallback 메시지 처리

### 5) AI 추천 로직
- 자연어 입력을 구조화된 요구사항으로 변환
- 인원, 예산, 목적, 분위기, 식사/카페 우선순위 추출
- Kakao 데이터 기반으로 후보 비교
- 추천 이유 생성
- “사실 기반” 원칙 적용: 확인되지 않은 정보는 생성하지 않음

### 6) Dining Plan 생성
- 추천 식당 1개 선정
- 해당 식당 근처 카페 1개 선정
- 식사 → 이동 → 카페의 타임라인 구성
- 카페 변경, 재추천, 결과 카드 등 UI 구성

### 7) 지도 연동
- 사용자 위치와 추천 위치 마커 생성
- 식당/카페 중심 표시
- 지도와 카드 상태 연결
- Marker 클릭 시 상세 정보 표시

### 8) 에러 처리와 배포
- 위치 거부, API 실패, LLM 실패, 결과 없음 대응
- 로딩 상태와 진행 상태 표시
- Vercel 배포 환경 구성
- 실제 서비스 동작 점검

## 2. 구현 순서 상세

### Phase 1: 기초 구조 정리
- 앱 기본 레이아웃 결정
- 검색 입력 화면, 로딩 화면, 결과 화면 구성
- 상태 관리 구조 설계
- 디자인 토큰 정리

우선순위가 높은 이유:
- 이후 기능들이 모두 이 구조 위에 붙기 때문입니다.
- 시안의 좌측-우측 구조를 그대로 유지하면 개발 속도가 빨라집니다.

### Phase 2: 위치 + 검색 기반 핵심
- Geolocation API 연결
- 현재 위치를 중심으로 Kakao Local 호출
- 검색 결과를 UI에 카드 형태로 표시
- 사용자 입력 조건에 따라 검색어 변형

이 단계가 완료되어야 실제 “추천 후보”가 만들어집니다.

### Phase 3: AI 분석 단계
- 사용자 문장을 구조화
- 선택형 조건을 표준 포맷으로 변환
- Kakao 결과를 GPT에 전달해 비교
- 추천 이유 생성
- 가짜 정보 방지 규칙 적용

이 단계는 서비스의 차별화 포인트입니다.

### Phase 4: Dining Plan 생성
- 식당 후보 선정
- 근처 카페 후보 탐색
- 최종 plan 생성
- 이동 거리와 시간 표시
- 카드형 결과 UI 구성

이 단계에서 “맛집 찾기”가 아닌 “오늘의 계획”이 완성됩니다.

### Phase 5: 지도 + UX 보완
- 지도 마커 표시
- 결과와 지도 동기화
- 모바일 반응형 보완
- 로딩 중, 실패 상태, 빈 결과 상태 정리

### Phase 6: 배포 검증
- 서버/프론트 환경 변수 정리
- 실제 호출 테스트
- Vercel 배포
- 공용 URL에서 기능 확인

1. 화면 설계

3. Kakao 검색 연동

6. 지도와 결과 동기화
7. 에러 처리
8. 배포 검증

이 순서는 가장 현실적입니다. 특히 Kakao 데이터와 지도 기능이 먼저 안정화되어야 GPT 추천이 정상적으로 의미를 갖습니다.

---

## 4. 구현 시 주의할 점

- GPT는 “확인 가능한 사실”만 근거로 사용해야 합니다.
- 주차 가능 여부, 분위기, 가격대 같은 값은 확인되지 않으면 추정하지 않습니다.
- MVP에서는 단일 식당 + 단일 카페 plan으로 제한하는 것이 좋습니다.
- 지도와 추천 결과를 같은 상태로 유지해야 UX가 자연스럽습니다.
- 시간 제한이 8시간이므로 기능 확장보다 “동작하는 MVP 완성”을 우선해야 합니다.

---

## 5. 최종 권장 전략

가장 안정적인 방식은 다음입니다:

- Frontend에서 입력, 위치, 지도, 결과 상태 관리
- 서버 프록시를 통해 Kakao/OpenAI 호출 처리
- GPT는 추천 조건 추출과 후보 비교에 집중
- 최종 결과는 지도 + 카드 + 타임라인으로 표현
- 디자인은 시안의 따뜻한 톤과 좌측 패널 구조를 그대로 유지

이 구조가 문서와 디자인 의도를 가장 잘 반영합니다.

원하면 다음 단계로 넘어가서, 이 계획을 바탕으로 실제 구현 파일 구조와 컴포넌트 분리까지 더 구체적으로 작성해드릴게요.
