# AI Dining Plan — Google Stitch UI/UX Design Prompt

## 1. 작업 목적

첨부한 **「AI Dining Plan 프로젝트 개발명세서.md」**를 프로젝트의 최우선 요구사항으로 사용하여, 실제 서비스 수준의 **UI/UX 디자인을 설계하고 `design.md` 문서를 작성하라.**

이 프로젝트는 단순한 맛집 검색 서비스가 아니다.

핵심 컨셉은 다음과 같다.

> **“맛집을 찾아주는 AI가 아니라, 지금 내 상황에 맞는 ‘오늘의 식사 계획’을 만들어주는 AI”**

사용자가 자연어 또는 간단한 조건을 입력하면,

**사용자 상황 분석 → 주변 맛집 탐색 → AI 추천 → 식당 + 카페로 구성된 Dining Plan 생성 → 지도에서 경로 확인**

까지 하나의 자연스러운 경험으로 연결되는 서비스다.

따라서 UI도 단순한 맛집 목록/지도 서비스가 아니라,

**“AI에게 오늘의 식사를 부탁하고, AI가 나에게 맞는 하나의 계획을 만들어주는 경험”**

을 중심으로 설계하라.

---

# 2. 가장 중요한 작업 원칙

첨부된 `AI Dining Plan 프로젝트 개발명세서.md`의 기능과 범위를 반드시 먼저 분석하라.

개발명세서에 정의되지 않은 대규모 기능을 임의로 추가하지 마라.

특히 MVP가 1일 8시간 개인 온라인 Vibe Coding 프로젝트라는 점을 고려하여,

* UI는 세련되어야 하지만 구현은 현실적이어야 한다.
* 지나치게 복잡한 인터랙션을 만들지 않는다.
* 로그인, 결제, 소셜 기능, 리뷰 작성, 복잡한 회원 시스템 등을 추가하지 않는다.
* Supabase/DB 기반의 복잡한 기능을 디자인하지 않는다.
* 핵심 경험인 **AI 추천 + 맛집 + 카페 + 지도**에 집중한다.

---

# 3. 벤치마킹 방향

국내 대표 맛집/지도 서비스의 UI/UX 패턴을 참고하라.

다음 서비스를 주요 벤치마크 대상으로 삼는다.

### Benchmark 1 — 네이버지도

참고할 요소:

* 통합 검색 UX
* 주변 장소 발견
* 장소 카드
* 지도 + 리스트 결합
* 저장/관심 장소
* 장소 상세 정보
* 검색 결과와 지도 간의 자연스러운 연결

단, 네이버지도의 복잡한 기능을 그대로 복제하지 말고,

**AI Dining Plan에 필요한 패턴만 추출하여 단순화한다.**

---

### Benchmark 2 — 카카오맵

참고할 요소:

* 지도 중심 탐색
* 주변 추천
* 장소 검색
* 지도 Marker
* 장소 카드
* 지도와 리스트의 연결
* 현재 위치 중심 UX

특히 이 프로젝트는 Kakao Local API와 Kakao Maps를 사용하므로,

**카카오맵의 지도 기반 장소 탐색 UX를 자연스럽게 참고한다.**

그러나 결과 화면이 카카오맵의 복제품처럼 보이지 않도록 한다.

---

### Benchmark 3 — 캐치테이블

참고할 요소:

* 사용자의 목적/조건을 빠르게 선택하는 UX
* 검색 조건의 간결한 표현
* 장소 카드의 정보 구조
* 이미지 중심의 맛집 표현
* 사용자가 “어디를 갈지” 빠르게 결정하도록 돕는 UX

특히

**지역 + 방문 목적 + 조건**

을 빠르게 입력할 수 있는 UX를 참고한다.

---

### Benchmark 4 — 다이닝코드

참고할 요소:

* 맛집 중심의 정보 구조
* 장소 탐색
* 음식점 정보 카드
* 사진 중심 콘텐츠
* 사용자가 맛집을 발견하는 경험

다만 AI Dining Plan에서는 맛집을 많이 보여주는 것보다,

**AI가 선택 이유를 설명하고 최종적으로 하나의 식사 계획을 제안하는 것**

에 더 집중한다.

---

### Benchmark 5 — 국내 최신 맛집/AI 추천 서비스

추가적으로 현재 국내에서 사용되는 AI 맛집 추천 서비스의 다음 UX 패턴을 참고하라.

* 자연어로 원하는 상황 설명
* “오늘 뭐 먹지?”와 같은 conversational UX
* 위치 기반 추천
* 카드 스와이프/선택
* AI 추천 결과
* 추천 이유를 자연어로 설명
* 지도와 추천 결과의 결합

단, 특정 서비스의 화면을 그대로 복제하지 말고 **UX 패턴만 참고한다.**

# 4. 최신 UI 트렌드 반영

2026년 최신 웹/앱 UI 트렌드를 적극적으로 반영하라.

다만 “트렌디해 보이기 위한 장식”이 아니라 실제 UX 개선에 도움이 되는 요소만 사용한다.

### 적용할 트렌드

#### 4.1 AI-native UI

AI 기능이 별도의 챗봇 화면처럼 분리되어 있지 않고,

서비스의 핵심 UX 자체에 AI가 자연스럽게 녹아들도록 설계한다.

예:

> “오늘 저녁 어디가 좋을까?”

입력

↓

> “청라에서 아내와 조용히 저녁을 먹고 카페에서 이야기하고 싶어요.”

↓

AI가 사용자의 상황을 분석

↓

> “데이트 / 2명 / 저녁 / 약 7만원 / 조용한 분위기”

↓

추천 결과

이 흐름이 자연스럽게 느껴져야 한다.

---

#### 4.2 Conversational Search

검색창을 단순한 키워드 검색창처럼 만들지 않는다.

예:

> “아내와 청라에서 데이트하려고 해. 저녁은 맛있는 걸 먹고 조용한 카페에서 이야기하고 싶어. 7만원 정도 생각하고 있어.”

이런 문장을 자연스럽게 입력할 수 있는 **AI Prompt/Search UI**를 디자인한다.

Placeholder 예:

> “오늘 누구와 어디서 무엇을 하고 싶은지 이야기해보세요…”

---

#### 4.3 Visual-first UI

맛집 서비스이므로 텍스트만 나열하는 UI를 피한다.

가능하면:

* 음식 이미지
* 큰 장소 이미지
* 이미지 중심 Card
* 핵심 정보만 간결하게 표시
* 충분한 여백
* 명확한 Typography

를 사용한다.

다만 실제 MVP에서는 Kakao API가 제공하는 데이터 범위에 맞춰 이미지가 없는 경우에도 UI가 깨지지 않도록 설계한다.

---

#### 4.4 Bento UI

필요한 화면에서는 Bento 스타일의 정보 배치를 활용한다.

예:

```text
┌─────────────────────────────┐
│ AI 추천 맛집                 │
│                             │
│        Restaurant           │
│                             │
└─────────────────────────────┘

┌──────────────┐ ┌────────────┐
│ 예산          │ │ 거리        │
│ 70,000원      │ │ 1.2km       │
└──────────────┘ └────────────┘

┌─────────────────────────────┐
│ ☕ 다음 코스                  │
│ 조용한 카페                   │
└─────────────────────────────┘
```

하지만 모든 화면을 억지로 Bento 형태로 만들지는 않는다.

---

#### 4.5 Low-stimulus UI

맛집 서비스라고 해서 색상과 카드와 Badge를 과도하게 사용하지 않는다.

전체적으로:

* 깨끗한 배경
* 충분한 여백
* 제한된 Accent Color
* 명확한 Typography
* 낮은 시각적 복잡도

를 유지한다.

---

#### 4.6 Micro Interaction

적절한 수준의 마이크로 인터랙션을 사용한다.

예:

* AI 분석 중 loading animation
* 추천 결과 등장 animation
* 지도 Marker 선택
* 카드 hover
* “다른 카페 추천” interaction
* 조건 Chip 선택
* AI 추천 완료 상태

단, 과도한 애니메이션은 사용하지 않는다.

---

#### 4.7 AI 처리 상태 표현

AI가 작업하고 있다는 느낌을 자연스럽게 제공한다.

예:

```text
AI가 당신의 상황을 분석하고 있어요
      ● ● ●

청라 주변 맛집을 찾고 있어요
      ✓

식사 후 가기 좋은 카페를 찾고 있어요
      ○
```

단순한 Spinner 하나보다,

**AI가 무엇을 하고 있는지 이해할 수 있는 Progressive Feedback UI**

를 설계한다.

# 5. 핵심 UX

AI Dining Plan의 가장 중요한 UX Flow를 다음과 같이 설계한다.

## Step 1. Home

첫 화면에서 사용자가 바로 서비스를 이해할 수 있어야 한다.

핵심 메시지:

> **오늘 뭐 먹을지, AI가 계획해드릴게요.**

Sub text:

> 지금의 상황과 원하는 분위기를 알려주세요.

큰 AI 입력창:

> “오늘 누구와 어디서 무엇을 하고 싶은지 이야기해보세요…”

그리고 자연어 입력 아래에 간단한 조건 Chip을 제공한다.

예:

```text
혼자
연인
친구
가족

식사
카페
술
데이트

가까운 곳
가성비
주차
조용한 곳
분위기 좋은 곳
```

예산:

```text
2만원
5만원
7만원
10만원+
```

# 6. 자연어 + 선택형 조건 UX

두 가지 입력 방식이 서로 경쟁하지 않도록 설계한다.

### 방식 A

자연어 입력

> “아내와 청라에서 조용하게 데이트하고 싶어요.”

### 방식 B

조건 선택

```text
누구와
[연인]

무엇을
[식사] [카페]

중요한 조건
[조용한 곳] [주차] [가까운 곳]

예산
[5만원] [7만원]
```

두 방식 모두 최종적으로 동일한 구조화된 사용자 요구사항으로 연결된다.

# 7. AI 분석 화면

사용자가 검색을 실행하면 AI 분석 화면을 보여준다.

예:

```text
오늘의 식사 계획을 준비하고 있어요

✓ 데이트
✓ 2명
✓ 청라
✓ 저녁
✓ 약 70,000원

주변 맛집을 찾는 중...
```

전체 과정은 너무 길지 않게 한다.

---

# 8. AI 추천 결과 화면

이 프로젝트에서 가장 중요한 화면이다.

단순히:

```text
맛집 1
맛집 2
맛집 3
```

처럼 보여주지 않는다.

최상단에 **AI가 추천하는 하나의 Dining Plan**을 강조한다.

예:

```text
오늘의 Dining Plan

🍽 저녁
[추천 식당]

☕ 카페
[추천 카페]

AI 추천 이유
“데이트하기 좋은 조용한 분위기와
예산 조건을 고려했어요.
식사 후 카페까지 도보 약 5분 거리입니다.”
```

추천 음식점 Card에는 다음 정보가 명확하게 보이도록 한다.

* 음식점 이름
* 카테고리
* 거리
* 주소
* AI 추천 이유
* 주요 조건
* Kakao Map 상세보기
* 지도에서 보기

예:

```text
┌──────────────────────────────┐
│                              │
│       Restaurant Image       │
│                              │
├──────────────────────────────┤
│ ○ ○ ○ 추천                   │
│                              │

│                              │

│                              │
│ [지도에서 보기]               │
└──────────────────────────────┘
```

# 10. AI 추천 이유

AI 추천 이유는 UI에서 중요한 차별화 요소다.

단순히:

> “맛있는 음식점입니다.”

와 같은 일반적인 문구는 사용하지 않는다.

사용자의 조건과 연결된 설명을 보여준다.

예:

> “아내와 조용하게 이야기할 수 있는 장소를 원하셨기 때문에, 청라에서 가까우면서 데이트 목적에 잘 맞는 곳을 우선 고려했어요.”

또는:

> “7만원 예산과 2인 저녁 식사를 고려하면 부담 없이 선택할 수 있는 후보예요.”

단, 실제 API가 제공하지 않는 정보를 사실처럼 표현하지 않는다.

확인되지 않은 정보는 단정하지 않는다.

# 11. Dining Plan UI

AI Dining Plan의 핵심 차별화 기능이다.

단순한 추천 리스트가 아니라 **시간의 흐름이 있는 하나의 계획**으로 보여준다.

예:

```text
TODAY'S DINING PLAN

01
🍽 DINNER

○○ 레스토랑
19:00
청라동 · 1.2km

        ↓
     도보 5분

02
☕

○○ 카페
20:30
청라동 · 350m
```

각 단계를 Timeline 또는 Vertical Journey 형태로 표현한다.

---

# 12. 지도 UI

Kakao Map을 활용한다.

지도는 단순히 전체 화면을 차지하는 것이 아니라,

**AI가 만든 Dining Plan을 시각적으로 이해시키는 역할**

을 하도록 설계한다.

지도에는:

* 현재 위치
* 추천 음식점 Marker
* 추천 카페 Marker
* 순서 번호
* 필요하면 연결 Line

을 표시한다.

예:

```text
       ☕ ②
        │
        │ 350m
        │
       🍽 ①
        │
      현재 위치
```

---

# 13. 지도 + 카드 Interaction

사용자가 지도 Marker를 클릭하면 해당 장소 Card가 강조되어야 한다.

반대로 Card를 클릭하면 지도에서 해당 Marker가 강조된다.

즉,

**List ↔ Map 양방향 Interaction**

을 디자인한다.

---

# 14. 다른 장소로 변경하기

추천 결과가 마음에 들지 않을 경우 전체 검색을 다시 시작하게 하지 않는다.

예:

```text
☕ 카페가 마음에 안 드나요?

[다른 카페 추천]
```

버튼을 누르면 AI가 기존 Dining Plan의 식당은 유지하면서 카페만 다시 추천한다.

이 기능은 MVP에서 실제 구현이 어려울 경우 UI/UX 설계에만 반영하고 개발명세서 범위를 넘어서는 구현은 강요하지 않는다.

# 15. Responsive Design

웹앱이므로 Desktop과 Mobile을 모두 고려한다.

### Desktop

좌측:

AI 추천 결과 / Dining Plan

우측:

Kakao Map

예:

```text
┌────────────────────┬──────────────────────────┐
│                    │                          │
│  AI Dining Plan    │                          │
│                    │       KAKAO MAP          │
│  Restaurant        │                          │
│                    │         🍽               │
│  ↓                 │                          │
│  Cafe              │              ☕          │
│                    │                          │
└────────────────────┴──────────────────────────┘
```

### Mobile

세로 구조로 전환한다.

```text
AI 입력
↓
AI 분석
↓
추천 식당 Card
↓
Dining Plan
↓
지도
↓
카페 Card
```

지도는 적절한 높이의 Bottom Sheet 또는 Card 형태로 사용할 수 있다.

# 16. Visual Design Direction

전체적인 디자인 방향은 다음과 같이 설정한다.

### 키워드

**Modern · Warm · Premium · Calm · Food-first · AI-native**

맛집 서비스이지만 배달앱처럼 복잡하거나 상업적인 느낌을 주지 않는다.

또한 지도 서비스처럼 차갑고 기능적인 느낌만 강조하지 않는다.

**“친구가 오늘 어디 갈지 골라주는 느낌”**

을 목표로 한다.

---

# 17. Color System

색상은 과도하게 사용하지 않는다.

추천 방향:

* Background: Warm White / Off White
* Text: Deep Charcoal
* Primary: 음식/식욕을 연상시키는 따뜻한 Accent
* Secondary: Soft Beige / Warm Gray
* AI 관련 요소: 은은한 Gradient 또는 Accent

단, 지나치게 강한 빨강/주황 계열을 전체 UI에 사용하지 않는다.

전체 화면의 약 70~80%는 Neutral 영역으로 유지한다.

---

# 18. Typography

한글 가독성을 최우선으로 한다.

권장 방향:

* Pretendard 또는 유사한 현대적 Sans-serif
* 큰 Heading
* 충분한 Line-height
* 정보 Hierarchy 명확화
* 카드 내부 텍스트 과밀 방지

Typography만으로도 정보 구조가 명확하게 느껴져야 한다.

---

# 19. Card Design

Card는 모두 동일한 크기의 반복적인 카드로 만들지 않는다.

중요도에 따라 hierarchy를 준다.

### Hero Card

오늘의 대표 추천 식당

### Secondary Card

카페

### Information Card

예산 / 거리 / 조건

### AI Insight Card

AI 추천 이유

Card에는 지나치게 많은 Border와 Shadow를 사용하지 않는다.

---

# 20. Chip / Badge

조건 표현에 적극적으로 사용한다.

예:

```text
저녁
청라

```

단, Badge를 너무 많이 사용하지 않는다.

가장 중요한 조건 3~5개만 보여준다.

# 21. Empty / Error / Loading State

실제 서비스 수준의 디자인을 위해 반드시 포함한다.

### 위치 권한 거부

```text
현재 위치를 확인할 수 없어요.

주소나 지역을 직접 입력하면
주변 맛집을 찾아드릴게요.

[지역 입력하기]
```

### 검색 결과 없음

```text
조건에 맞는 장소를 찾지 못했어요.

검색 범위를 조금 넓혀볼까요?

[검색 범위 넓히기]
```

### AI 분석 중

```text
당신의 오늘을 위한
Dining Plan을 만들고 있어요.
```

### API 오류

사용자가 기술적인 오류 메시지를 보지 않도록 한다.

나쁜 예:

> 401 Unauthorized

좋은 예:

> 잠시 문제가 발생했어요.
> 다시 한 번 시도해주세요.

# 31. 중요한 금지사항

다음 사항은 반드시 지켜라.

1. 개발명세서에 없는 핵심 기능을 임의로 추가하지 않는다.
2. 기존 맛집 서비스의 화면을 그대로 복제하지 않는다.
3. 특정 서비스의 브랜드 컬러를 그대로 사용하지 않는다.
4. 단순한 “맛집 검색 앱”처럼 디자인하지 않는다.
5. AI Chatbot 화면 하나만 만들어놓고 AI 서비스라고 하지 않는다.
6. 지도만 크게 보여주는 지도 서비스 형태로 만들지 않는다.
7. 지나치게 많은 정보를 한 화면에 넣지 않는다.
8. 사용자가 선택해야 할 항목을 과도하게 늘리지 않는다.
9. AI 추천 이유는 사용자 조건과 연결하여 표현한다.
10. 확인되지 않은 음식점 정보를 사실처럼 표현하는 UI를 만들지 않는다.

> **“검색하는 서비스가 아니라, 결정하게 도와주는 서비스.”**

그리고

이 두 가지가 모든 화면과 컴포넌트에 일관되게 반영되어야 한다.

# 33. 최종 작업 지시

이제 첨부한 `AI Dining Plan 프로젝트 개발명세서.md`를 먼저 분석한 뒤,

1. 국내 대표 맛집/지도 서비스의 UX 패턴을 참고하고
2. 2026년 최신 AI-native / Visual-first / Bento / Conversational UX 트렌드를 반영하고
3. AI Dining Plan의 차별화된 UX를 정의하고
4. 실제 구현 가능한 Design System을 만들고
5. 화면별 상세 UI/UX 사양을 정의하고
6. 개발자가 바로 구현할 수 있는 수준의 `design.md`를 완성하라.

**디자인의 핵심은 “맛집 검색”이 아니라 “AI가 만들어주는 오늘의 식사 계획”이다.**

최종 디자인은 **Modern + Warm + Premium + Calm + Food-first + AI-native**의 방향으로 완성하라.
